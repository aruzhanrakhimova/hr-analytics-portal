## 1. Обзор продукта

### 1.1 Назначение

HR Аналитический Портал — корпоративная веб-платформа для кадровых и социальных подразделений, обеспечивающая централизованный сбор, хранение, визуализацию и анализ кадровых данных по головной компании, более чем 70 дочерним организациям и подрядным компаниям. Система предназначена для автоматизированной подготовки аналитических документов с использованием ИИ.

### 1.2 Проблема

Кадровые данные о фонде оплаты труда, численности, обучении, рекрутинге и социальных проектах разрозненно хранятся в различных системах и файлах (Excel, Word, PDF, PowerPoint). Подготовка любой аналитической справки занимает значительное время, данные устаревают, сопоставление информации по 70+ компаниям вручную неэффективно.

### 1.3 Решение

Единая платформа с:
- централизованной базой данных кадровых показателей;
- возможностью загрузки и автоматического разбора файлов любых форматов;
- ИИ-генерацией готовых документов (справки, письма, презентации, отчёты);
- будущей интеграцией с учётными системами компании (1С, SAP и др.).

### 1.4 Целевая аудитория

**Первичные пользователи (Этап 1):** ~70 сотрудников кадровых и социальных подразделений.

**Вторичные пользователи:** руководство компании (получатели отчётов), IT-служба (администрирование и интеграции).

## 2. Цели и метрики успеха

### 2.1 Бизнес-цели

- Сократить время подготовки аналитической справки с нескольких часов до 5–10 минут.
- Обеспечить единый источник правды по кадровым показателям для всех 74+ компаний.
- Снизить количество ошибок при ручном агрегировании данных.
- Автоматизировать регулярную отчётность для руководства.

### 2.2 KPI продукта

| Метрика | Целевое значение |
|---------|-----------------|
| Время генерации отчёта | < 2 минут |
| Охват компаний в базе | 100% (74+) |
| Одновременных пользователей | до 70 |
| Поддерживаемые форматы файлов | PDF, XLSX, XLS, DOCX, DOC, PPTX, PPT, CSV, TXT |
| Доступность системы | 99.5% в рабочее время |

## 4. Архитектура системы

### 4.1 Текущий прототип (Этап 1)

Одностраничное веб-приложение (SPA) на чистом HTML/CSS/JavaScript без серверной части. Данные хранятся в памяти браузера (объект `store`). ИИ-функции реализованы через прямые вызовы Anthropic API (`claude-sonnet-4-6`).

**Технологический стек прототипа:**
- Frontend: HTML5, CSS3, Vanilla JavaScript (ES6+)
- Графики: Chart.js 4.4.0
- Парсинг Excel: SheetJS (xlsx) 0.18.5
- ИИ: Anthropic API (`claude-sonnet-4-6`, `max_tokens: 1000`)

### 4.2 Целевая архитектура (Этап 2+)

```
[Браузер пользователя]
       ↓ HTTPS
[Frontend SPA] ←→ [Backend API (REST/GraphQL)]
                         ↓
                   [База данных (PostgreSQL / Oracle)]
                         ↓
              [Интеграционный слой]
               ├── 1С / SAP (учётные системы)
               ├── Файловое хранилище (S3 / MinIO)
               └── ИИ-сервис (Anthropic API / внутренний LLM)
```

### 4.3 Интеграции (Roadmap)

- **Фаза 1:** Ручной ввод и загрузка файлов.
- **Фаза 2:** Импорт из учётных систем (1С ЗУП, SAP HR) по расписанию.
- **Фаза 3:** Real-time синхронизация данных через API учётных систем.

## 5. Модули системы

### 5.1 Дашборд (`/dashboard`)

**Назначение:** Главная страница с агрегированными KPI и быстрым доступом ко всем разделам.

**Функциональность:**

- Панель сводных показателей (KPI-карточки):
  - Количество компаний в базе
  - Среднесписочная численность (всего по группе)
  - ФОТ фактический (млрд ₸) с отклонением от плана
  - Затраты на обучение с динамикой к прошлому году
  - Принято на работу в текущем году
  - Количество активных социальных проектов

- Графики:
  - График «ФОТ план vs факт» по месяцам (столбчатый, Chart.js)
  - Диаграмма структуры численности: адм. / произв. / аутстаффинг (кольцевая)

- Таблица топ-5 компаний по численности (адм. / произв. / аутстаффинг)
- Лента последних действий пользователей (загрузки, создание отчётов, добавление компаний)

**Фильтры:** не применяются (глобальный вид).

### 5.2 Фонд оплаты труда (`/payroll`)

**Назначение:** Ведение плановых и фактических данных по ФОТ в разрезе категорий персонала и компаний.

#### 5.2.1 Структура данных

| Поле | Тип | Описание |
|------|-----|----------|
| `company` | string | Наименование компании |
| `type` | enum | Дочерняя / Подрядчик |
| `period` | string | Год, квартал или месяц |
| `admPlan` | number | ФОТ адм. персонала — план (тыс. ₸) |
| `admFact` | number | ФОТ адм. персонала — факт (тыс. ₸) |
| `prodPlan` | number | ФОТ произв. персонала — план |
| `prodFact` | number | ФОТ произв. персонала — факт |
| `outPlan` | number | ФОТ аутстаффинга — план |
| `outFact` | number | ФОТ аутстаффинга — факт |
| `conPlan` | number | ФОТ подрядных орг. — план |
| `conFact` | number | ФОТ подрядных орг. — факт |

#### 5.2.2 Функциональность

- Таблица ФОТ по всем компаниям с вычисляемым % исполнения (факт / план × 100%)
- Цветовая индикация исполнения: зелёный (≥95%), жёлтый (>100%), красный (<95%)
- Фильтрация по: году, кварталу (Q1–Q4), типу компании (дочерняя / подрядчик)
- Форма добавления данных (модальное окно) с полями для всех категорий персонала
- Экспорт таблицы в Excel (.xlsx)
- Графики:
  - Сравнение структуры расходов ФОТ по категориям (столбчатый, план vs факт)
  - Отклонение факта от плана по компаниям в % (столбчатый, цветовая кодировка)

#### 5.2.3 Бизнес-правила

- Данные по аутстаффингу для подрядных организаций не вводятся (поле отображается как «—»).
- % исполнения считается по совокупному ФОТ (сумма всех категорий).
- Возможность быстрого добавления данных по подрядным компаниям без изменения справочника.

### 5.7 Управление документами (`/documents`)

**Назначение:** Загрузка, хранение и ИИ-анализ файлов с кадровыми данными.

#### 5.7.1 Поддерживаемые форматы

| Формат | Расширения | Обработка |
|--------|-----------|-----------|
| Excel | `.xlsx`, `.xls` | Парсинг SheetJS → автоматическое извлечение данных |
| PDF | `.pdf` | Загрузка + ИИ-анализ содержимого |
| Word | `.docx`, `.doc` | Загрузка + ИИ-анализ |
| PowerPoint | `.pptx`, `.ppt` | Загрузка + ИИ-анализ |
| CSV | `.csv` | Парсинг → автоматическое извлечение |
| Текст | `.txt` | Загрузка + ИИ-анализ |

#### 5.7.2 Функциональность

- Зона загрузки файлов: drag-and-drop и клик для выбора (множественный выбор)
- Индикатор прогресса обработки каждого файла
- Список загруженных документов со статусами: Обработка / Обработан / Ошибка
- Кнопка «Анализ» для каждого файла — запускает ИИ-разбор
- ИИ-анализ файла выдаёт:
  1. Предположительное содержимое файла на основе его названия
  2. Перечень ключевых показателей для извлечения
  3. Рекомендации — в какие разделы базы данных импортировать данные
  4. Что необходимо проверить перед импортом
- Кнопки «Импортировать» / «Отклонить» после просмотра анализа
- Для Excel-файлов — немедленный парсинг и отображение количества строк

#### 5.7.3 Сценарий обработки Excel

1. Пользователь перетаскивает файл `.xlsx` в зону загрузки.
2. SheetJS читает первый лист файла.
3. Система определяет тип данных (ФОТ / численность / обучение / рекрутинг).
4. ИИ формирует рекомендации по импорту.
5. Пользователь подтверждает импорт → данные добавляются в соответствующий раздел.

### 5.8 Генерация отчётов (`/reports`)

**Назначение:** ИИ-генерация готовых документов на основе данных из базы системы.

#### 5.8.1 Типы генерируемых документов

| Тип | Описание | Объём |
|-----|----------|-------|
| Аналитическая справка | Структурированный анализ с выводами и динамикой | 600–1000 слов |
| Тезисы для презентации | 8–10 слайдов: заголовок + 3–4 буллета с цифрами | 400–600 слов |
| Деловое письмо | Официальный стиль, обращение, суть, запросы | 200–400 слов |
| Краткая справка | Ключевые цифры и выводы | 200–300 слов |
| Развёрнутый отчёт | Полная структура с разделами и рекомендациями | 1500–2500 слов |
| Служебная записка | Стандартная форма (Кому/От/Дата/Тема) | 300–500 слов |

#### 5.8.2 Параметры генерации

| Параметр | Варианты |
|----------|----------|
| Раздел данных | Все разделы / ФОТ / Численность / Обучение / Рекрутинг / Соц. проекты |
| Период | 1 полугодие / квартал / месяц / год (выбор пользователя) |
| Адресат | Свободный ввод (Председатель Правления / Совет директоров и т.д.) |
| Охват | Все дочерние / конкретная компания / подрядчики / топ-10 |
| Доп. инструкции | Произвольный текст (акценты, сравнения, требования к стилю) |

#### 5.8.3 Функциональность

- Выбор типа документа через визуальные карточки
- Настройка параметров перед генерацией
- ИИ получает реальные данные из store (ФОТ, численность и т.д.) и вставляет конкретные цифры
- Вывод результата в прокручиваемой области с форматированием
- Кнопки: «Копировать в буфер обмена», «Скачать как .txt»
- Индикатор состояния «Генерация...» во время обработки

#### 5.8.4 Промпт-инжиниринг

Промпт включает:
- Данные по ФОТ всех компаний из `store.fotData`
- Сводные KPI (численность, обучение, рекрутинг, соц. проекты)
- Выборку социальных проектов из `store.socialProjects`
- Тип документа, период, адресат, охват, доп. инструкции
- Чёткое требование к формату вывода в зависимости от типа

**Модель:** `claude-sonnet-4-6`, `max_tokens: 1000`

## 7. Функциональные требования

### 7.1 Ввод данных

- **FR-01** Система должна позволять вводить данные ФОТ по каждой компании в разрезе: адм. персонал, произв. персонал, аутстаффинг, подрядчики — план и факт.
- **FR-02** Система должна позволять вводить данные по численности в разрезе: категория, пол, возраст, пенсионеры, квалифицированные работники.
- **FR-03** Система должна позволять вводить данные по затратам на обучение по типам обучения — план и факт.
- **FR-04** Система должна позволять вводить данные о найме/увольнении и затратах на рекрутинг и оценку за произвольный период.
- **FR-05** Система должна позволять добавлять социальные проекты с указанием типа, стоимости, сроков, региона и статуса.
- **FR-06** Система должна позволять добавлять новые компании (дочерние и подрядные) в справочник.

### 7.2 Просмотр и аналитика

- **FR-07** Дашборд должен отображать актуальные сводные KPI по всем компаниям группы.
- **FR-08** Все таблицы должны поддерживать фильтрацию и сортировку.
- **FR-09** Система должна автоматически вычислять % исполнения ФОТ (факт / план × 100%).
- **FR-10** Система должна автоматически вычислять показатель текучести кадров.
- **FR-11** Система должна автоматически вычислять стоимость одного найма.
- **FR-12** Графики должны строиться в реальном времени на основе данных в системе.

### 7.3 Работа с файлами

- **FR-13** Система должна принимать файлы форматов: PDF, XLSX, XLS, DOCX, DOC, PPTX, PPT, CSV, TXT.
- **FR-14** Для Excel/CSV файлов — автоматически считывать содержимое и определять количество строк.
- **FR-15** ИИ-анализ должен давать рекомендации по импорту данных из загруженного файла.
- **FR-16** Загрузка файлов должна поддерживать drag-and-drop и стандартный диалог выбора.

### 7.4 Генерация документов

- **FR-17** Система должна генерировать 6 типов документов: аналитическая справка, тезисы для презентации, деловое письмо, краткая справка, развёрнутый отчёт, служебная записка.
- **FR-18** Генерируемые документы должны содержать реальные данные из базы системы (конкретные цифры, названия компаний).
- **FR-19** Пользователь должен иметь возможность задавать: период, адресата, охват компаний, дополнительные инструкции.
- **FR-20** Готовый документ должно быть возможно скопировать в буфер обмена и скачать в виде файла.

### 7.5 Экспорт

- **FR-21** Любую таблицу системы должно быть возможно экспортировать в Excel (.xlsx).

## 8. Нефункциональные требования

### 8.1 Производительность

- **NFR-01** Время загрузки страницы: < 3 секунд на стандартном подключении.
- **NFR-02** Время генерации ИИ-документа: < 30 секунд.
- **NFR-03** Время обработки загруженного Excel-файла (до 10 000 строк): < 5 секунд.
- **NFR-04** Одновременная работа 70 пользователей без деградации производительности.

### 8.2 Совместимость

- **NFR-05** Браузеры: Chrome 100+, Firefox 100+, Edge 100+, Safari 15+.
- **NFR-06** Адаптивность: корректное отображение на экранах шириной от 1280px (рабочие станции).

### 8.3 Безопасность (для целевой архитектуры)

- **NFR-07** Аутентификация через корпоративный SSO (LDAP / Active Directory).
- **NFR-08** Разграничение доступа на уровне ролей (RBAC).
- **NFR-09** Все данные передаются по HTTPS (TLS 1.2+).
- **NFR-10** Аудит-лог всех действий пользователей (кто, что, когда изменил).

### 8.4 Надёжность

- **NFR-11** Доступность системы: 99.5% в рабочее время (08:00–20:00).
- **NFR-12** Резервное копирование базы данных: ежедневно.
- **NFR-13** Graceful degradation: при недоступности ИИ-сервиса остальные функции системы продолжают работать.

### 8.5 Локализация

- **NFR-14** Интерфейс полностью на русском языке.
- **NFR-15** Валюта: тенге (₸). Числовой формат: `1 234 567` (пробел как разделитель тысяч).
- **NFR-16** Даты: `ДД.ММ.ГГГГ` или `Месяц ГГГГ` для периодов.

## 9. Ограничения текущего прототипа

| Ограничение | Описание | Решение в Этапе 2 |
|-------------|----------|-------------------|
| Нет персистентности | Данные теряются при перезагрузке страницы | PostgreSQL / Oracle БД |
| Нет аутентификации | Любой пользователь имеет полный доступ | Интеграция с корп. SSO |
| Нет API ключа | ИИ-функции требуют Claude.ai или dev-среды с ключом | Backend-прокси к Anthropic API |
| Нет реального экспорта Excel | Кнопка показывает уведомление, файл не создаётся | Генерация через SheetJS на backend |
| Нет реальной загрузки в БД | «Импорт» из файлов не записывает данные в store | ETL-пайплайн на backend |
| Нет ролей | Один общий интерфейс | RBAC на backend |
| Нет многопользовательского режима | SPA работает локально в браузере | Web-сервер + БД + API |

## 12. Глоссарий

| Термин | Определение |
|--------|-------------|
| ФОТ | Фонд оплаты труда |
| Адм. персонал | Административно-управленческий персонал |
| Произв. персонал | Производственный (рабочий) персонал |
| Аутстаффинг | Персонал, предоставленный сторонней организацией (работает на площадке, но оформлен у аутстаффера) |
| Подрядчик | Самостоятельная подрядная организация со своим персоналом |
| Дочерняя компания | Юридически самостоятельная организация, входящая в группу компаний |
| Среднесписочная численность | Среднее значение списочной численности за каждый день расчётного периода |
| Текучесть кадров | Уволившиеся / среднесписочная численность × 100% |
| KPI | Key Performance Indicator — ключевой показатель эффективности |
| SSO | Single Sign-On — единая корпоративная аутентификация |
| RBAC | Role-Based Access Control — управление доступом на основе ролей |
| SPA | Single Page Application — одностраничное веб-приложение |
| ETL | Extract, Transform, Load — процесс извлечения, преобразования и загрузки данных |
